## 1. P2 — Signed-in callers lose sibling tabs because their identity is never sent

Location: `src/views/RecordistBooth.vue:69` (`loadTabs`, request headers).

Concrete failing input: a signed-in God admin opens `/r/human_aran_cym_n` on a device without a stored key for `human_aran_eng`, with grace mode on. The Welsh booth opens, but the English sibling tab is omitted even though the server explicitly permits God admins to see it. The request carries only `x-booth-keys`, if any; it never carries Authorization. `recordist-router.cjs:440` consequently passes `user: null`, and `booth-tabs.cjs:106` excludes the sibling. This also defeats the signed-in artist path when sibling keys have not already been cached. The navbar's separate `/mine` request does not repair this: the booth does not reload tabs when those keys arrive.

Smallest fix: obtain the signed-in access token through `useAuth().getAccessToken()` before fetching tabs and include its Bearer Authorization header alongside the held-key header. Ensure auth restoration has completed before treating the caller as signed out.

Verification: added `presents the signed-in identity when asking which sibling voices may be opened` to `src/views/RecordistBooth.test.js`, using the existing component/router harness and a mocked available access token. ## 2. P2 — Recording from a sheet row leaves the previous take playing into the microphone

Location: `src/views/RecordistRoom.vue:1606` (`recordFromSheet`; new row button at line 493).

Concrete failing input: on the ready screen with recorded lines 1 and 2, open Lines & settings, press Play on line 1, then press Again on line 2 before playback ends. `recordFromSheet` closes the sheet and calls `recordOne`, which starts the microphone and reveals line 2 without calling `stopPlayback`. Line 1 continues playing while line 2 is recorded. The sheet's playback control disappears, and speaker output can be captured and filed as the new line's take. Playback started while ready does not set `micHeld`, so the live-playback hold does not protect this path.

Smallest fix: call `stopPlayback()` before starting the microphone in `recordFromSheet` (or centrally before `recordOne` starts capture).

Verification: added `stops the sheet playback before opening the mic from a row` to `src/views/RecordistRoom.batchLines.test.js`. It plays line 1 through a stateful Audio stub, presses the row's recording button for line 2, confirms that line 2 is on the live stage, and asserts playback has stopped. On the exact merged production code it fails: playback remains true. The other eight tests in that file pass. Actual acoustic contamination was not measured; continued playback alongside the live stage is reproduced with mocked audio and microphone.
