## 3. P1 — new parallel workers can exceed MAX_CHARS

Location: `tools/audio/revoice-seeds-to-cast.cjs:190-191,198,216`.

Failing input: `PARALLEL=5 MAX_CHARS=100`, with five distinct outstanding 100-character asks that each require a render. Each worker checks out.spent=0 and passes the limit before any POST resolves. All five requests are dispatched and can spend 500 characters. This was serial before the reviewed change; the concurrency addition invalidates the existing spend check. The provider limiter only limits simultaneous calls, not this run's character allowance.

Smallest fix: synchronously reserve each ask's worst-case characters before awaiting POST; include outstanding reservations in the limit and reconcile them with the reported actual spend on completion. A serial run when MAX_CHARS is set would also preserve the limit.

## 4. P2 — planner merges questions with statements and different word spacing

Location: `tools/audio/plan-first-render.cjs:180-182`.

Failing input: same-language course slots `Tu viens?` and `Tu viens.`. add() uses tokenise(text,false).key, which strips both punctuation and spaces, so these become one universe entry. The plan prices one recording and silently drops the other, contrary to `services/shared/text-normalize.cjs`, where a question mark is explicitly part of recording identity. Under --outstanding, an existing statement can even set have=true on a missing question. Likewise `a name` and `an ame` collide despite different word boundaries. These are deduplication errors before strict/loose cut rules run.

Smallest fix: build the universe identity with normalizeForAudio rather than punctuation-free character tokens, and keep distinct required recording identities throughout plan()/verifyPlan instead of dropping equal token keys. Containment tokens can remain separate from recording identity.
