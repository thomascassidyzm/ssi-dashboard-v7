## 2. [P2] SQL comments can reject an otherwise valid primary-key lookup

**Location:** `services/shared/agent-db.cjs:40` (raw SQL matching at lines 42–45, enforced at line 88).

**Failing input:** `client.query('SELECT id FROM course_audio WHERE id = $1::uuid /* replaces id::text = $1 */', ['0b7f3c8e-1d2a-4c5b-9e6f-7a8b9c0d1e2f'])`.

**Observed:** The wrapper rejects with `AGENT_DB_LINT` before sending this keyed query because it matches the old expression inside the block comment. The same problem affects SQL string literals containing the pattern. Adding a diagnostic comment must not change whether a safe statement can execute; the documented recommendation to explain/fix the old query can itself trigger this failure.

**Smallest fix:** In the runtime SQL lint path, mask SQL comments and string literals before matching, preserving character offsets for diagnostics. Keep source-file linting separate: simply masking JavaScript string literals in `lintFiles()` would suppress its intended SQL checks.

**Exactly what ran:** `./node_modules/.bin/vitest run services/shared/agent-db.lane-review.test.cjs`. Its second test failed with `AGENT_DB_LINT` instead of resolving. The real wrapper and a mocked raw client were used; the safe statement was never sent. No live database was involved.

## 3. [P2] A query-config callback is dropped on refusal

**Location:** `services/shared/agent-db.cjs:92`.

**Failing input:** `client.query({ text: 'SELECT id FROM course_audio WHERE id::text = ANY($1)', values: [[]], callback: handleError })`.

**Observed:** `handleError` is never invoked; the wrapper returns a rejected promise instead. A callback-style caller normally ignores the return value, so its error/completion path never runs and the rejection can terminate the process under Node's default unhandled-rejection behaviour. The installed `pg` implementation explicitly supports `config.callback`: `pg/lib/query.js:23` reads it, and `pg/lib/client.js:539` creates a promise only when there is no callback. The wrapper checks only positional callbacks in `rest`, breaking the returned pg Client's query contract.

**Smallest fix:** Resolve the effective callback from the positional arguments or `q.callback` before rejecting; deliver the lint error through that callback when present and retain promise rejection otherwise.

**Exactly what ran:** `./node_modules/.bin/vitest run services/shared/agent-db.lane-review.test.cjs`. Its third test failed because the callback error was `undefined`. The test consumes the incorrect rejection to avoid an unrelated test-runner crash. The callback omission is verified; process termination was not separately executed.
