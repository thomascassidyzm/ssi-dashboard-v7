## 1. High: overrides are installed into the wrong systemd manager

**Location:** `tools/qa-copy/install.sh:8`, `:15–16`.

**Failing input:** run the installer as Tom on the existing installation. All five scheduled QA services are system units running as `popty`, but the installer writes their overrides to `$HOME/.config/systemd/user` and reloads only the user manager. The active system timers therefore continue launching services with the live owner DATABASE_URL. The new copy never receives their heavy scans.

**Evidence:** the committed service definitions in `tools/qa/{audio-gap,sibling-identity,debut-practice,voice-variety,voice-policy}/systemd/` all declare `User=popty` and load `/etc/popty/owner.env`. Host inspection returned `/etc/systemd/system/ssi-audio-gap.service` and `/etc/systemd/system/ssi-voice-variety.service`, both with empty `DropInPaths`; all five system timers were active, while the inspected user audio-gap and voice-variety timers were disabled and inactive.

**Smallest fix:** install/remove the five QA overrides under `/etc/systemd/system/<unit>.service.d/` and reload the system manager. Use an explicit `/home/tomcassidy/ssi-restore/qa-copy.env` path there, and remove the cross-manager `Wants`/`After` dependency on the user postgres service (or move that service into the same manager). Keep the refresh infrastructure in the user manager if desired.

## 2. High: failed switch still deletes the serving database

**Location:** `tools/qa-copy/refresh.sh:95–97`.

**Failing input:** an existing `qa-copy.env` names database A, the restore of B succeeds, but writing `qa-copy.env.tmp` or renaming it fails. For example, `qa-copy.env.tmp` is an existing directory: the redirect at line 95 fails. The script uses `set -uo pipefail`, without `-e`, and neither operation has a failure handler. It continues through line 97, dropping A because A differs from NEWDB=B. The unchanged environment file still points every subsequent QA connection at the deleted A. This breaks the promised make-before-break behaviour and can still end with the success message.

**Smallest fix:** attach `|| fail "publishing QA copy environment"` to the entire write-and-rename compound command. Do not write the new state or enter database cleanup unless publication succeeds. The existing `fail` helper then preserves SERVING=A and removes the unserved B.
