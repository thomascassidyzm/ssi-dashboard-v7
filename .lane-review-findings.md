## 1. [P1] A failed count authorises a destructive watchdog restore

**Location:** `services/course-builder/lib/redo-snapshot.cjs:236` (new `requireEmpty` guard).

**Failing input:** the watchdog restores snapshot A with `require_newest:true, require_empty:true`. The seed now contains a freshly submitted LEGO and no phrases. The LEGO HEAD/count request returns `{ count:null, error:{ message:'statement timeout' } }`; the phrase count returns zero; the snapshot query succeeds and finds no newer snapshot.

**Proof:** `restoreViaUndoRoute` in `services/course-builder/lib/redo-watchdog.cjs:205-211` sends both guards, and `services/course-builder/routes/build.cjs:390-402` passes them to `restoreSnapshot`. In `redo-snapshot.cjs:207-212`, both count requests discard `error`. At line 236, `null || 0` treats the failed LEGO read as an empty seed. Lines 240-242 then call `wipeSeedTeaching`, deleting the new LEGO before restoring the older snapshot. The new safety condition therefore fails open precisely when it cannot establish emptiness. The count reads pre-date this range, but using their unchecked values as permission to delete is new here.

**Smallest fix:** retain and check both count errors, and refuse `requireEmpty` restores unless both counts were successfully obtained. Never coerce an unknown count to zero for this decision.

## 2. [P2] Valid female-form recordings cannot be linked to their intended seat

**Location:** `services/shared/link-clip.cjs:115-122`.

**Failing input:** `POST /api/production/ita_for_eng/link-clip` with `{ "links":[{ "seedNumber":1, "role":"target1", "audioId":"11111111-1111-4111-8111-111111111111" }], "dryRun":true }`, where seed 1 has `target_text:"sono sicuro"` and an empty target1 slot; the named clip has the same label, the correct target1 cast voice, and a current-revision spoken verdict `"sono sicura"`; the course's stored expansion is `expanded_f:"sono sicura"`.

**Proof:** the new check compares the verdict only with raw `row.target_text`, so it returns `SPOKEN_WORDS_MISMATCH` before the voice check or pointer write. This contradicts the target-seat contract implemented in this same range: `services/shared/render-gender-prep.cjs:46-49` selects `expanded_f` for target1; `services/shared/audio-render-entry.cjs:484-495` turns that reading into `spokenText` and a verdict during a re-record; `services/phases/phase8-audio-v13.cjs:5951-5955` stores the verdict while retaining the original label. A clip correctly repaired through the render door therefore becomes impossible to attach through link-clip to another empty female slot with that same row text. This input assumes the stated rows; no claim is made that seed 1 currently contains them.

**Smallest fix:** for target1/target2, compare the spoken verdict with the stored reading for that course, row text and seat (expanded_f / validated expanded_m, falling back to row text). Keep the existing label and cast checks; known and pod slots should retain their own words checks.

## 3. [P2] Gender prep can report the female reading while returning the old male take

**Location:** `services/shared/audio-render-entry.cjs:269-275`.

**Failing input:** render `{ courseCode:"ita_for_eng", role:"target1", text:"sono sicuro", purpose:"fill missing target1", requestedBy:"review-example", dryRun:true }`. The stored expansion is `expanded_f:"sono sicura"`; the library contains a clip in the resolved target1 voice labelled `"sono sicuro"`, saying the original male words, with no spoken verdict.

**Proof:** lines 269-271 compute `said:"sono sicura"`, but `ident` was constructed from the original request at line 264 and is passed unchanged to `deps.link` at line 274. `services/phases/phase8-audio-v13.cjs:5564-5570` implements that dependency using the original text. The early return consequently supplies the male take and echoes `renderText:"sono sicura", genderPrep:"stored"`. Real requests take the same early return. **Smallest fix:** carry the expected spoken reading into the library lookup and validate candidates against it before the early return, while retaining the original row text as the filing/linking label. A candidate known only by its male label cannot establish that it speaks the required female form.

## 4. [P2] Discarding or replacing a proposal during Apply loses its Undo action

**Location:** `services/course-editor/course-editor-router.cjs:268-275` (also replacement at line 255).

**Failing input:** two admin tabs have pending proposal P for a Korean phrase. Tab A posts `/proposals/P/apply`; after A reads P but while it awaits `liveRow`, `clipsFor` or the edit door, tab B deletes `/proposals/P`. Equivalently B proposes a replacement for the same line while P still has status `pending`.

**Proof:** Apply claims P at lines 300-306, but the `inflight` set is consulted only by Apply and Undo. Delete at lines 268-275 removes the still-pending record without consulting it; the replacement loop at line 255 does the same. `proposal-store.cjs:42-55` serialises individual file mutations, not the complete Apply operation. A continues with its captured record and commits the edit at lines 319-328. `patchProposal` at lines 293-296 then finds no P and returns undefined, so lines 335-341 return success without a proposal containing `undoOps`. GET cannot list P, and Undo at lines 353-354 refuses it as `nothing to undo`. The edit door separately saves an undo file, so this is loss of the editor's proposal/Undo contract, not destruction of every recovery copy.

**Smallest fix:** make both discard and pending-proposal replacement reject any affected proposal in `inflight`, checking inside the serialised mutation as well. An applying proposal must remain stored until its applied status and undo have been persisted.
