## P2 — A non-text operation is presented as the author and date of a text change

Location: `services/voice-engine/recordist-router.cjs:552–557` (especially line 557).

The new `textChangeEditors` lookup unconditionally converts the row's `last_edit_event_id` into `changedBy` and `changedAt`. That pointer records the latest content operation, not necessarily the operation that changed this line's words. The new UI then explicitly says `text changed by <actor>, <date>` (`src/views/recordist/rerecord-list.js:46`).

Concrete failing input: a decomposed, unflagged, unapproved seed has an orphan take saying `dw i 'di bod yn brysur iawn`, current target text `dw i wedi bod yn brysur iawn`, and no replacement recording for this reader. Alice changed those words on 14 October. Bob subsequently mass-approves the seed on 16 October. `services/course-builder/routes/build.cjs:453–459` stamps Bob's event into `last_edit_event_id` while changing only `approved_at`. The seed still qualifies for the re-record list, but the new lookup supplies Bob and 16 October; the card says `text changed by Bob, 16 Oct`, although Bob never changed its text. Audio linking can cause the same false attribution: `services/shared/link-clip.cjs:176–178` stamps an audio-only operation on seeds and phrases.

Smallest safe fix: fetch enough event information to establish that the event actually changed this line's text field, and populate the attribution only when that is established. For approvals, audio links, edits to another role's text, or events without sufficient evidence, leave the attribution absent so the existing `text changed after your take` fallback is used. Recovering the original author from history can follow separately.

No cheap existing router test harness covers the private `textChangeEditors` function; a regression test was not added.
