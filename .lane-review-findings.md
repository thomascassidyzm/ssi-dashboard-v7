## P2 — Refused takes accumulate into false batch completion

Location: `src/views/recordist/booth-home.js:73–76`, consumed by `src/views/RecordistRoom.vue:2874` (`withLocalRecorded`).

Concrete failing input: a two-line sentence batch has no server-recorded lines. Read A: `commit()` adds A to `doneIds`, and the watcher credits A. The server refuses A; `isRecorded(A)` now returns false (`RecordistRoom.vue:885–887`), but `creditLoadedBatch` retains A. Read B successfully: credit becomes `[A, B]` although A remains outstanding. `withLocalRecorded` converts that length into two uploading lines, so the home screen treats the batch as finished and Up next skips it. The same retention applies when an editable line's words change and its take is cleared.

This range changes a maximum observed count into a union of all historically recorded IDs. In this example the previous implementation retained a count of one; the new implementation reaches two and falsely completes the batch.

Smallest fix: once the served batch matches the requested batch, replace that batch's credited IDs with the IDs currently satisfying `isRecorded`, rather than unioning them with historical IDs. Preserve entries for other batches and the existing served/scope guard.
