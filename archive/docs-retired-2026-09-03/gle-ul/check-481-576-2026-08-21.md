# Ulster Irish correctness pass — seeds 481–576, the missing fourth block

**Why this pass exists.** Four correctness workers were dispatched overnight on 2026-08-20 over the
668 translated seeds of `gle_ul_for_eng`. Three reported and published: 1–192, 193–384, and
385–480 + 577–668. The fourth, on 481–576, hit an account rate limit at 22:30 and never produced a
check file — not a late result, a failed one. Kai read those 96 seeds himself in the interim and
said plainly that his own read is weaker coverage than an independent pass, because he wrote the
spec they were judged against. This pass is that independent re-check, run against the same spec
(`docs/gle-ul/ulster-dialect-spec.md`) and the same brief (`scripts/gle-ul/check-brief.md`) the
other three workers used.

## Correction notice — this replaces an earlier version of this report

The first version of this pass reported `caidé` at seeds 493/494/572 and `dada` at seed 485 as new
defects. **Both were false.** Kai checked against the live database and found `goidé`/`a dhath`
already in place at all four seeds, version 3, timestamped 22:44 on 20 August — hours before this
pass ran.

**Root cause, stated plainly because it matters more than the fix:** the first pass read seed text
from `scripts/gle-ul/all-translations.json`, an on-disk snapshot, instead of querying
`course_seeds` directly. That file was frozen before the §1e/§1e-bis normalisation sweep landed, so
it silently disagreed with the database on exactly the four seeds that sweep touched. This is the
report-instead-of-data trap the brief warns about, and it is exactly what happened.

A full diff of the on-disk JSON against a fresh `course_seeds` pull for this window found **4
mismatches out of 96 seeds — 485, 493, 494, 572 — and no others.** So every other verdict in this
report (89 of the original rows) was checked against text that happens to be byte-identical to the
live database; only these four needed correcting.

**Corrected against live `course_seeds` this time, with two things fixed in method:**
- **Mutation-tolerant matching.** Postgres regex uses `\y` for a word boundary, not `\b` — `\b` in
  Postgres's advanced regex silently matches nothing (confirmed: `'bhog muid' ~* '\bmuid\b'` is
  `false`, `'bhog muid' ~* '\ymuid\y'` is `true`). My first live query used `\b` and would have
  produced exactly the kind of false zero this correction is about, on plain ASCII text, before any
  accented character was even involved.
- **Calibrated on a known-present form before trusting any zero.** Whole-course, `\y`-bounded, live:
  `goidé` = 43, `a dhath` = 4, `muid` = 37 — all non-zero, confirming the query pipeline actually
  works before I asked it for a zero. Only then: whole-course live `caidé` = 0, `dada` = 0.

## Defect

**Discontinuous predicate — seed 552.**

| seed | English | current Irish (live) | should be |
|---|---|---|---|
| 552 | the church at the other end of the village is ugly | `tá an séipéal ag an cheann eile den tsráidbhaile gránna` | `tá an séipéal atá ag an cheann eile den tsráidbhaile gránna` |

The predicate adjective `gránna` is separated from its subject `an séipéal` by the entire locative
phrase (`ag an cheann eile den tsráidbhaile`) sitting between them, reading as though the phrase
itself is what's ugly rather than the church. Genuine word-order defect — independently flagged in
the block-6 build report's own self-check as well; this pass confirms it rather than discovering it
fresh.

## Doubts

- **Seeds 481, 482 — `fíordhóchas`.** Live text: `is é an t-aon fhíordhóchas atá fágtha againn é`
  (481), `is é an t-aon fhíordhóchas nach bhfuil siad dáiríre` (482). Not an Ó Dónaill headword; a
  live FGB lookup (`scripts/gle-ul/fgb.cjs fíordhóchas`) returned no dictionary section. It's a
  transparent `fíor-` compound, not obviously wrong, but it is an unattested coinage for "real hope,"
  and the translator's own note already flags the uncertainty. A Donegal speaker should look rather
  than either of us guessing.
- **Seed 493 — `a thiocfas`.** Live text: `goidé a thiocfas ansin?` — `goidé` is correct (see
  correction above); what's left is the `-as`/`-eas` relative-future ending on `thiocfas`, for
  standard `thiocfaidh`. Whole-course live grep for this ending pattern found it nowhere else in the
  668 seeds. It's textbook-associated with Munster relative futures rather than Ulster ones; neither
  the spec nor the Wikipedia Ulster Irish article it draws on confirms or denies it for Donegal, so
  this is a doubt, not a defect.
