> future agent push the audio-encoding fix to **production (live)** correctly,
> without repeating the mistakes we hit on stage. Read this whole doc before

---

## 1. The bug (one paragraph)

iOS / AVPlayer fails to play many of our MP3s — distortion on standalone clips,
and playback that **stops after the first segment** in concatenated lesson audio
(intro/presentation screens). Root cause: the files were written by **ffmpeg's
MP3 muxer** (`Lavf*`/`Lavc*` encoder), which prepends an **ID3v2 wrapper** and a
bogus **`enc_padding=1152`** LAME-extension field. CoreAudio (iOS) chokes on
both. Android's MediaPlayer is lenient, which is why it only showed on iOS.
**The fix:** re-encode through the real `lame` binary (clean Xing+LAME header,
no ID3v2). `-codec:a libmp3lame` inside ffmpeg does **not** fix it — the bug is
in the muxer, not the encoder. See memory `mp3-encoding-ios-bug.md`.

## 4. How to push to live (procedure)

> ⚠️ Verify each step against the current dashboard/tooling — some specifics
> below should be re-confirmed, they're flagged with **CONFIRM**.

### Per-course, the safe order is:

1. **Make sure the course's manifest in `course-configs` (`author` branch) is the
   fixed version** (duration-synced, version bumped). Pull latest on apidev:
   `cd ~/course-materials/course-configs && git fetch && git reset --hard origin/author`
   (apidev has had divergent-branch issues; hard-reset to origin/author is the
   clean move once you know origin is correct).

2. **Stage first, always.** Deploy to stage and let **Step 2** run — it now
   does the format check. **Every audio must be correctly encoded (0 format
   failures) and durations must match (0 diff).** If Step 2 shows format
   failures, those files are still broken — re-master them (see §5) before going
   further.

3. **Run the external validator** (Imdad's timing tester v3) against the deployed
   course — it checks format + duration end-to-end via the API the app uses:
   ```
   cd /tmp/.../audio_timing_tester && source venv/bin/activate
   python main.py --course-id en-fr --email <you>@saysomethingin.com --check-format --workers 5
   ```
   It now uses **sox** for duration (we patched `audio_analyzer.py`). Expect
   0 mismatches, 0 format failures. (Imdad's standalone `check_mp3_format.sh`
   does the same format check on a folder of files.)

4. **Manual smoke test** on a real iOS device and a real Android device (~5–10
   min each), per Imdad's process ask. Confirm intro/presentation audio plays
   through (that's the concat path that the bug broke).

5. **Get Allion's confirmation** before live, so any incoming issue can be
   localised to a known recent deploy.

6. **Deploy to live.** **CONFIRM the exact mechanism** — most likely one of:
   - The dashboard export **Step 4** (per memory `export-step-meanings.md`,
     Step 4 = the **stage→prod audio copy**), OR
   - On apidev: `cd ~/course-tool && ./check -e live deploy ~/course-materials/course-configs/Courses/<course>.json`
     (the `./check` tool's envs are `stage, live, dev, qa`).
   Whichever it is, it copies the clean stage audio + manifest into `ssiborg-assets`
   / the prod-serving location. **Run the live duration check after** (the deploy
   tool's `durations` command uses sox) and expect 0 diffs.

### Hard rules (learned the hard way — see memories):

- **NEVER run two stage/live deploys in parallel.** They've caused duration
  diffs before. Serial only. (`parallel_stage_deploys_unsafe.md`)
- **Coordinate with the tech team for `overwrites_different` situations** — going
  live can overwrite prod audio that other things depend on.
  (`coordinate_tech_on_overwrites.md`, `overwrites-different-misleading.md`)
- **PM2 → apidev SSH needs the agent socket forwarded** after any logout:
  `pm2 restart production-api --update-env` (with `ssh-add -l` showing your key).
  (`pm2-needs-ssh-agent-socket.md`)
- **apidev `./check` quirks:** put `-e <env>` BEFORE the command, not after
  (it uses `order!` and stops at the first positional). It exits 0 even on
  "Failed". `./check fix-durations` (hyphenated) not `fixdurations`. Ruby is only
  on PATH in a login shell — use `bash -lc '...'` and `rvm use 3.3.6@course-deploy`.
  (`check-tool-quirks.md`, `stage-deploy-timing.md` — deploys take ~40min–1.5h.)

## 5. ⚠️ The combined-presentation trap (this caused hours of pain)

**Combined-presentation audio** (the intro-screen clips: narration + target1 +
target2 concatenated) is the ONE category that:
- is **NOT in `course_audio`** — it lives only in S3 + is referenced by the
  deployed manifest (`role: "presentation"` samples), and
- is **regenerated by Step 1 of the export every time it runs.**

Consequences:
- **Do NOT run Step 1 export after duration-syncing a course.** It regenerates
  the combined audio, which shifts their durations, breaking the manifest match.
  If you must re-export, **re-sync durations afterward** (Step 2 / fix-durations).
- If combined-presentation files are broken and you need to fix them **without**
  shifting duration, the correct method is **re-concatenate** (re-run Step 1 with
  the lame fix in place) or **remux** (`ffmpeg -c copy -map_metadata -1`, strips
  ID3, keeps frames). **Do NOT "re-master/re-encode"** an already-combined file —
  decoding + re-encoding adds a *second* layer of LAME priming/remainder padding
  (~10–17ms), which shifts the duration and won't match the manifest.
  - `sox` measures *decoded samples*; the broken file and a fresh re-concat have
    the same decoded length, so they match. A re-encode of the combined file
    does not. This is why "just re-encode it" fails for combined presentations.
- See memory `combined-presentation-audio-bug.md` and the long debugging arc.

## 6. Verifying / fixing residual broken files

- **Find broken files** (ID3v2 / non-LAME) without downloading whole files:
  `scripts/fixes/find-unmastered-mp3s.cjs --keys-file <keys.txt> --concurrency 16`
  (512-byte S3 Range reads). Produces `unmastered-keys.txt`.
- **Re-master S3 files in place** (with backup):
  `scripts/fixes/remaster-mp3-headers.cjs --execute --concurrency 8 --no-update-duration [--no-drift-check] --keys-file <keys.txt>`
  Backs up to `mastered_backup_lavf/`, re-encodes via lame, verifies clean header.
  Writes new durations to `logs/duration-journal.jsonl`.
- **Apply journaled durations to Supabase** (batch, id-lookup, fast):
  `scripts/fixes/apply-duration-journal.cjs --execute`
  (Note: `course_audio.s3_key` is unindexed — never UPDATE by s3_key in bulk;
  these scripts journal + batch by id. See `supabase-s3key-unindexed.md`.)
- **NEVER re-master combined presentations with these scripts** (they re-encode →
  double-pad). For those, re-concatenate (Step 1) or remux. See §5.
